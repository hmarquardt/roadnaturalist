# Offline preparation

`build-ecoregions.py` prepares the EPA Oregon Level III/IV dataset from pinned shapefile ZIPs. `build-roads.py` prepares the Oregon road-centerline pilot from pinned U.S. Census Bureau TIGER/Line 2025 county ROADS ZIPs, writes the road GeoParquet, the test snapshot fixture, and the manifest entry, and can print a read-only EPA overlap check. `build-road-network.py` builds the bounded discovery road-network extract from the same pinned county archives: every ROADS feature of a discovery-relevant TIGER class whose vertices lie inside the habitat analysis window, with per-class and excluded-class counts recorded in the manifest, plus the offline extraction summary fixture (`tests/fixtures/or-roads-network.summary.json`) that the browser run is checked against. `tiger_sources.py` holds the shared source constants, digest verification, archive reader, and the geometry helpers both road scripts use. `build-habitat.py` prepares the bounded Oregon wetland and hydrography datasets from a pinned U.S. Fish & Wildlife Service National Wetlands Inventory state GeoPackage and pinned U.S. Geological Survey NHD High Resolution HU8 extracts. It verifies source digests, selects the analytical window with the GeoPackage's own R-tree index, clips, simplifies, reprojects and measures in DuckDB Spatial, writes both GeoParquet artifacts and their manifest entries, and supports `--verify` (synthetic spatial-math fixtures), `--corridors` (real pilot metrics written to the test expectations fixture), and `--verify-artifacts` (offline digest/readability/expectation check).

`verify-occurrence-live.mjs` is not a data-preparation script: it is the opt-in live check for the occurrence adapters (iNaturalist public API, eBird when `EBIRD_API_KEY` is present). It is read-only, needs no cache, prints per-corridor source summaries, and prints SKIP for eBird without a credential. It never prints or persists the key.

The preparation scripts verify source digests, keep raw source caches out of Git, and preserve dataset entries they do not build when rewriting `data/manifest.json`. Occurrence sources are live APIs rather than prepared artifacts, so they add no manifest entries.

`verify-investigator-live.mjs` is the opt-in live/operator check for the Investigator. It fetches every source declared in `src/investigator/sources.js`, checks each declared phrase against the text the source actually served (reporting drift against the reviewed capture), queries OpenStreetMap through the same adapter and mirror order the app uses, matches the mapped ways to the canonical TIGER/Line corridor, runs the real seven-stage pipeline, and prints the qualified access finding, restrictions, contradictions, unresolved items, and access-verification coverage. It needs no credential: the sources are public pages and Overpass needs no key. `--write-record` refreshes `data/investigator/or-pilot-access-evidence.json`, the reviewed capture the browser replays offline; live results never become fixture truth automatically. See `docs/INVESTIGATOR.md`.

`verify-investigator-worker.mjs` is the opt-in check for the Worker research boundary (`worker/`). With `INVESTIGATOR_WORKER_URL` set it requests every declared probe from the deployed Worker; without it, it serves the same handler over `127.0.0.1` in-process and exercises the boundary end-to-end against the real sources, printing the exact deployment step it skipped. Either way it reports, per probe, the HTTP result, extraction, cache state, drift against the committed baseline, and then coverage and the deterministic finding per corridor, plus timing and payload numbers. It needs no credential and never writes to the repository.

`validate-probes.mjs` (`npm run validate:probes`) is the offline reviewer check for the investigator probe catalog. It runs the committed JSON Schema plus the semantic rules a schema cannot express (unique ids, declared corridor references, repeated phrases, quoted windows and recurrences), then the server-side checks only the Worker can make (every declared source host allow-listed, every policy profile implemented, every probe buildable), and finally cross-checks the reviewed capture and the drift baseline against the catalog so a missing or stale entry is visible. It leads with the probe and the fact that is wrong, contacts no network, and exits non-zero only on errors — warnings are for a reviewer, not a gate.

`refresh-investigator-evidence.mjs` (`npm run investigator:refresh`) is the catalog-driven evidence refresh. It validates the catalog first, retrieves every declared probe through the same operator path the Investigator uses, rewrites `data/investigator/or-pilot-access-evidence.json` and `src/investigator/probes/drift-baseline.js` together, re-validates both, prints what changed per probe, and commits nothing: the diff is what a reviewer reads. `--check` validates and reports without retrieving or writing anything.


`verify-geometry.mjs` (`npm run verify:geometry`) is the offline check of the shared analytical-geometry boundary. It replays `tests/fixtures/discovery-geometry-failures.json` (the eight real corridors the buffering engine refused, with their geometry, failing radii, GEOS messages, and every repair variant that was tried) and eleven adversarial geometries through the same repair ladder the browser runs, then prints per corridor which rung was accepted, how much doubled centerline traversal it removed, the length delta, and the maximum displacement. It reads no dataset, contacts no network, writes nothing, and exits non-zero when a recorded failure is not repaired, when a repair exceeds the acceptance tolerances, or when some adversarial case is over-repaired. Use it after any change to road composition, segmentation, or geometry preparation.
`docs/ECOREGIONS.md`, `docs/ROADS.md`, `docs/DISCOVERY.md`, `docs/HABITAT.md`, `docs/OCCURRENCE.md`, and `docs/INVESTIGATOR.md` hold the exact commands, source digests, schemas, coverage extents, privacy rules, and scope. Generated small GeoParquet files are committed so local analysis works without production data hosting. `docs/DEPLOYMENT.md` holds the production topology (Pages project `roadnaturalist` for `roadnaturalist.com`, Worker `roadnaturalist-investigator` at `api.roadnaturalist.com`), its configuration, and every deploy and verification command.

`stage-pages.mjs` stages the static application for Cloudflare Pages direct upload: it copies `index.html`, `assets/`, `src/`, and `data/` into `dist/`, refuses to replace a `dist/` it did not create, and fails if any stylesheet, script, module import, or manifest dataset is missing or its byte length disagrees with `data/manifest.json`. It also refuses to stage the small files the browser loads by path rather than through the manifest — the pilot declaration, the discovery search areas, the reviewed access capture, and the probe catalog with its schema. `dist/` stays out of Git. `deploy-pages.mjs` runs it and uploads, but only from a clean `main` checkout whose HEAD is on `origin/main`, so what is published is always a reviewed commit.

`tests/production-live.spec.js` is the opt-in browser check of the deployed path (`npm run verify:production:browser`): it loads `roadnaturalist.com` (or `PRODUCTION_BASE_URL`), runs the access investigation for all three pilot corridors, and asserts that the boundary answered live, nothing was replayed while the boundary was healthy, coverage reached `FULL` whenever no source failed, and the browser itself never contacted an official source. Routine `npm run test:e2e` skips it.
